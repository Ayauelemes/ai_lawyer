# Состояние реализации AI ЖКХ LEGAL ENGINE

Продолжена разработка существующего репозитория. Рабочий контур запускается на macOS, использует исходный контракт точной проверки редакции и включает интерфейс, API и хранилище. Функциональный референс «Аудитор ЖКХ» был доступен в браузере. Из него взят сценарий перехода от описания ситуации к делу, документам и нормам. Архитектура, данные, дизайн и код собственные.

## Результат проверки

- На PostgreSQL 18.3 с pgvector 0.8.2 прошли все 16 тестов. Проверены миграции, поиск по тексту и векторам, изоляция дел и файлов, расчёты, экспорт, отказ при ложных ссылках и недопущенная передача данных.
- На SQLite прошли 15 тестов. Проверка, специфичная для PostgreSQL, пропущена.
- Проверены установка пакета, зависимости, запуск Uvicorn на macOS и выдача интерфейса, ресурсов и OpenAPI из установленного пакета. В браузере проверены входная страница и переключение языка. Реальные обращения, ключи провайдера и производственные юридические материалы в тестах не использовались.

## Следующий шаг к рабочему пилоту

1. В закрытом контуре выбрать модель и проверить с ней тестовый набор на русском и казахском языках. Оценивать полноту поиска, ошибки в реквизитах, подмену доказательств и выводы без правовых оснований.
2. Куратору сформировать первый допущенный корпус для выбранных региона, услуг и дат. Отдельно согласовать источник обезличенных судебных актов, МРП и правила санкций. Начать с затопления и начислений.
3. Настроить роли БД, изоляцию по строкам, управление ключами и резервными копиями, сроки хранения, внешний аудит и прокси с лимитами. Проверить разграничение на инфраструктуре компании. Шифрование отдельных полей не заменяет защиту диска и метаданных.
4. Если нагрузка требует параллельной обработки большого числа дел, вынести синхронные анализ, извлечение и экспорт в очередь с повторным запуском, лимитами и идемпотентностью. Измерить задержки на реальных размерах корпуса.
5. Утвердить юридические шаблоны, включая процессуальные реквизиты. Доработать анализ нескольких юридически значимых дат, переходных положений и сложных случаев административной ответственности по размеченным кейсам.

## Корпоративное рабочее пространство

Добавлены светлая и тёмная темы с сохранением выбора, адаптивная навигация, контекст выбранного дела, отдельные представления аргументации, проверки источников и студии документов. Аналитика получает агрегаты из нового API с фильтрацией по организации. Аргументация позволяет выбрать вывод и открыть связанную норму и документы в соседних панелях. Проверка редакции выполняется повторным запросом к каталогу.

Остаются задачи текущего расширения: полноценная история изменения полей дела, задачи и участники, сравнение редакций, свободное редактирование и сохранение проектов документов, граф с узлами фактов и полноценная проверка всех авторизованных экранов в браузере. Студия использует существующий экспорт и редактирование реквизитов и требований. Новые представления требуют дальнейшей пользовательской проверки.

## Тұрғындардың өтініштерін қабылдау / Публичная приёмная

Проект обнаружен после перемещения в `/Users/a1234/Desktop/ии юрист`; разработка продолжена в этой копии. Главный маршрут `/` теперь открывает отдельную RU/KK форму без авторизации. Кабинет перенесён на `/staff`, существующие защищённые API не ослаблены. Добавлены миграция 0003, public_submissions для идемпотентности, публичная конфигурация и POST приёма. Поддержаны контакт, адрес, текст, дата, согласие и один файл до 3 МБ. После транзакции возвращается непрогнозируемый номер. Обращение сразу доступно сотрудникам назначенной организации как дело с материалами и аудитом. Персональные данные не включены в ответ API; публичного чтения нет. Приём отключён по умолчанию, организация задаётся только сервером.

Проверка: 22 unittest, 21 успешен, 1 PostgreSQL-specific пропущен; JS синтаксис проверен. Новые тесты проверяют повтор запроса, конфликт, обязательное согласие, отсутствие управления tenant из формы, ограничения, шифрование контактов, DOCX-вложение, атомарный откат при неверном файле, отсутствие публичного доступа к делам, разделение `/` и `/staff`. Реальная отправка email/SMS, публичный просмотр статуса и интернет-развёртывание не реализованы. Для внешнего приёма требуются фактические реквизиты получателя, согласованная политика обработки, общий rate limiter и эксплуатационные настройки. Реальный LLM не подключён.
