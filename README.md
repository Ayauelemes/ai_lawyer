# AI ЖКХ LEGAL ENGINE

Локальное рабочее пространство для жилищно-коммунальных споров Республики Казахстан. Дела, документы, правовые источники, проекты заключений и проверка юристом доступны через веб-интерфейс и REST API.

## Запуск на macOS

Из корня репозитория с Python 3.11 или новее:

```sh
python3 -m venv .venv
source .venv/bin/activate
python -m pip install .
zhkh-legal init
zhkh-legal user-add --tenant company --name operator --role operator
zhkh-legal user-add --tenant company --name reviewer --role lawyer
zhkh-legal user-add --tenant company --name curator --role curator
zhkh-legal user-add --tenant company --name administrator --role admin
uvicorn zhkh_legal.api:app --host 127.0.0.1 --port 8000 --no-access-log --limit-concurrency 40
```

Откройте [рабочее пространство](http://127.0.0.1:8000/) и вставьте ключ нужной учётной записи. Команда выдаёт ключ один раз. Храните его в менеджере секретов. Команды `user-rotate` и `user-disable` принимают те же `--tenant` и `--name`. У каждой организации свои дела и журнал. Роли `curator` и `admin` управляют общим каталогом источников.

По умолчанию приложение использует SQLite и ключ шифрования из `local-data/data.key`. Сделайте закрытую резервную копию ключа отдельно от базы. Без ключа содержимое ранее зашифрованных записей не восстановить. Заголовки дел, имена файлов и часть служебных метаданных хранятся открыто внутри базы. Используйте шифрование диска и закрытый доступ к каталогу. На macOS для OCR изображений и сканов установите Tesseract с языками `rus`, `kaz`, `eng` (через Homebrew пакеты `tesseract` и `tesseract-lang`). Текстовые PDF и DOCX извлекаются без Tesseract.

### Подключение ИИ

В той же оболочке задайте URL совместимого с OpenAI API и имя установленной у провайдера модели. Например, для модели, уже запущенной локально:

```sh
export ZH_LLM_URL=http://127.0.0.1:11434/v1
export ZH_LLM_MODEL='имя-установленной-модели'
```

Перезапустите сервер. Провайдер должен поддерживать `/chat/completions` и JSON-ответ. Если провайдер требует ключ, передайте его в окружении как `ZH_LLM_KEY`. Для внешнего провайдера нужны HTTPS, утверждённая политика обработки, включение `ZH_ALLOW_CASE_TRANSFER=1` администратором и разрешение на передачу материалов при каждом запуске анализа. Перед включением проверьте, что за указанным loopback-адресом действительно работает локальная модель и она сама не пересылает данные.

Без подключённой модели можно вести дела, извлекать текст, искать в каталоге и рассчитывать санкции по допущенным правилам. Запрос анализа вернёт `llm_not_configured`. Для семантического поиска нужны PostgreSQL, `ZH_EMBEDDING_MODEL`, совместимый маршрут `/embeddings` с 1536 измерениями и предварительная индексация источников. Запросы анализа с данными дела проходят тот же контроль передачи. Индексация отправляет название и текст допущенного публичного источника, поэтому для судебных актов используйте обезличенные копии.

### Заполнение каталога

Раздел «Законодательство» содержит ссылки на официальные карточки актов. Их тексты и судебные акты включаются в анализ только после импорта проверенных версий. В административной панели куратор импортирует JSON, другой куратор или администратор сверяет снимок и утверждает. Форматы записи для нормы, судебного акта, МРП и правила расчёта приведены в [OpenAPI](http://127.0.0.1:8000/docs) и [руководстве по интеграции](docs/integration.md). Начните с небольшого корпуса для одного региона и известных дат. Используйте только источники, доступные на согласованных условиях.

### PostgreSQL и Docker

Для PostgreSQL без Docker предварительно создайте отдельную базу с доступным расширением pgvector, установите `ZH_DATABASE_URL` в формате `postgresql+psycopg://…` и выполните `zhkh-legal init`. Для Compose скопируйте `.env.example` в `.env`, задайте случайный URL-безопасный пароль БД и ключ Fernet. Сгенерировать ключ можно командой `python -c 'from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())'`. После этого:

```sh
docker compose up --build -d
docker compose exec app zhkh-legal user-add --tenant company --name administrator --role admin
```

Для нормального процесса проверки заведите также отдельные учётные записи оператора, юриста и куратора. При прямой установке переменные передаются через окружение, а `.env` читает Docker Compose. Порт Compose опубликован только на loopback.

### Проверки

```sh
PYTHONPATH=src python -m unittest discover -s tests -v
node --check src/zhkh_legal/static/workspace.js
```

Чтобы прогнать тот же набор на PostgreSQL, задайте `ZH_TEST_POSTGRES_URL` для отдельной тестовой базы. Тесты создают и удаляют изолированные схемы и могут установить pgvector. Тестовые данные синтетические и находятся только в тестах.

## Приём обращений жителей без регистрации

`/` — отдельная публичная форма RU/KK. `/staff` — существующий защищённый кабинет. API сотрудников по-прежнему требует Bearer-ключ. Публичная форма не показывает дела или документы другим посетителям.

Из текущего каталога проекта, после установки зависимостей и создания администратора:

```sh
PYTHONPATH=src .venv/bin/python -m alembic upgrade head
ZH_PUBLIC_TENANT=company ZH_PUBLIC_NAME='Название компании-получателя' PYTHONPATH=src .venv/bin/python -m uvicorn zhkh_legal.api:app --host 127.0.0.1 --port 8000 --no-access-log --no-proxy-headers
```

`ZH_PUBLIC_TENANT` должен совпадать с организацией активного администратора. Без переменной приём отключён; посетитель не может выбирать организацию. Настройку нужно передавать при каждом старте (для Compose — добавить её в environment). Поле `ZH_PUBLIC_NAME` показывается жителю как получатель. Перед внешним запуском укажите фактического получателя, согласуйте текст обработки данных и сроки хранения.

POST `/v1/public/complaints`: multipart-поле `payload` содержит JSON с request_id (UUID, повторять при сетевом сбое), title, narrative, address, region, name, contact, consent=true, language=ru/kk, event_on (необязательно). Допускается один `file` PDF/DOCX/JPG/PNG до 3 МБ. Подтверждение возвращает только reference и status=received; это номер сохранённой записи компании, не государственный регистрационный номер. Повтор идентичного request_id не создаёт второе дело. Изменённый запрос с тем же ID даёт 409.

Содержание и контакты зашифрованы в описании дела, файл — в существующем Evidence. Входящий запрос учитывается в аудите как resident.submit от технического пользователя без возможности входа. Внешняя LLM при приёме не вызывается. Публичного чтения или поиска статуса по номеру нет; ответов по email/SMS автоматически не отправляем.

Локальные ограничения: 5 попыток за 10 минут с одного адреса, 100 за час на процесс, лимит тела и проверка типа файла. Перед интернет-публикацией нужны общий лимитер на прокси/Redis, настройка доверенных прокси, защита от автоматической рассылки, антивирус для вложений и регламент обработки. Ограничения в памяти не являются распределённой защитой от DDoS.
