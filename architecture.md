# Архитектура

## Границы продукта и развертывание

Внутреннее приложение для специалистов ЖКХ и юристов Казахстана. Самостоятельный режим — установка в инфраструктуре компании или выделенном контуре с браузерным интерфейсом и собственной БД. Интеграционный режим использует тот же API и политику доступа. Основной сценарий: создать дело → уточнить факты → собрать доказательства и источники → получить проект → передать на проверку → экспортировать или отдать через API.

На первом релизе — модульный монолит. Python/FastAPI и Pydantic на границе; домен без зависимости от HTTP и LLM; SQLAlchemy, PostgreSQL с pgvector и миграциями Alembic; закрытое объектное хранилище; отдельный воркер для OCR, индексации, анализа и экспорта. Docker Compose для локального запуска. В эксплуатации API и воркеры масштабируются отдельно. Очередь на PostgreSQL с lease, лимитами, ограниченными повторами и идемпотентностью; отдельный брокер вводится при подтвержденной нагрузке. БД и векторы документов дел отделены логически от общего публичного корпуса; вложения и секреты не попадают в образы и исходный код.

## Модули и данные на их границах

| Модуль | Вход → выход | Механизм |
|---|---|---|
| Intake | Обращение, вложения → события, стороны, утверждения, требования, вопросы | Проверка форматов, OCR с указателями на страницу, структурированное извлечение; пользователь может исправить факты |
| Classification | Факты → категории, правовые вопросы, неопределенность | Таксономия и маршрутизация; многометочная классификация, отдельный статус вне области ЖКХ РК |
| Legislation Retrieval | Вопрос, юридически значимая дата, территория, язык → кандидаты | Точный адрес, PostgreSQL FTS и pgvector, объединение рангов; фильтры по версии, юрисдикции и допуску |
| Citation Verification | Адрес нормы и дата → точная редакция или код причины | Детерминированная проверка; отсутствующий пункт не заменяется статьей целиком |
| Judicial Practice | Вопрос и фактические признаки → аналоги с совпадениями и различиями | Поиск только в допущенном корпусе; судебный акт по конкретному делу маркируется как аналог, нормативные постановления учитываются отдельно |
| Legal Reasoning | Снимок фактов и источников → матрица условий, аргументы сторон, выводы | Правила для обязательных условий; LLM только структурирует проект с указателями на доказательства и источники |
| Liability & Penalty | Редакция правила, установленные условия, применимый МРП → трасса расчета или отказ | Версионированные правила и Decimal; административная санкция, договорные суммы и гражданский ущерб считаются раздельно |
| Document Generator | Версия заключения и шаблон → DOCX/PDF | Шаблоны, закрепленные шрифты, изолированный рендер, маркировка проекта |
| Quality Control | Проект и снимок анализа → замечания и решение о допуске | Схема, проверка ссылок, дат, цитат и чисел; содержательную применимость проверяет юрист |
| Integration API | Права и запрос клиента → дела, задания, результаты, артефакты | Версионированный REST/OpenAPI, роли, постраничный вывод, корреляция и идемпотентность |

Статусы фактов: сообщено стороной, подтверждено указанным доказательством, оспаривается, неизвестно. Утверждение извлечения не равно установленному факту. Даты события, расчетного периода, подачи и проверки хранятся отдельно. Для периода, пересекающего изменение закона, анализ делится по интервалам; переходные положения, действие во времени и применимость к лицу проверяются отдельно. Сроки и правовые основания не подставляются при неопределенности.

## Хранилище и происхождение

- Дела: `organization`, `membership`, `case`, `case_event`, `fact_assertion`, `evidence`, `analysis_run`, `opinion_revision`, `review_decision`, `audit_event`. Доказательство связывает версию файла, хеш и страницу или фрагмент. Анализ ссылается на неизменяемые версии фактов, источников, правил и конфигурации модели. Можно восстановить использованные входы; повтор генерации может отличаться.
- Законодательство: `act`, `source_snapshot`, `provision_locator`, `provision_revision`, `source_review`. Адрес включает акт, язык, статью, часть, пункт и подпункт. Редакция хранит текст, интервал `[effective_from, effective_until)`, источник, хеш снимка и время проверки; история редакций отделена от истории импорта и отзыва. Дата публикации не подменяет дату начала действия. Допущенные интервалы для одного адреса не пересекаются: ограничение БД и проверка в приложении. Для каждой редакции хранится основание определения периода действия и статус; открытый интервал не подтверждает будущие даты.
- Импорт: разрешенный канал → карантин и неизменяемый оригинал → разбор → сравнение текста и дат → проверка человеком → транзакционная публикация → обновление индекса. Повторный импорт идемпотентен по источнику и хешу. Исправление порождает новую запись, отзыв исключает запись из выдачи и ставит связанные заключения на повторную проверку. URL хранятся вместе со снимком исторической версии, поскольку текущая страница может измениться.
- Судебная практика: суд, дело, дата, категория, инстанция и стадия, факты, примененные нормы, результат, URL, происхождение и статус проверки. Обезличивание до индексирования. Различать «ничего не найдено», «корпус не покрывает вопрос» и «поиск недоступен». МРП и нормативные правила расчета имеют собственные версии и ссылки на основания; дата выбора МРП следует проверенному правилу конкретной санкции.

## Анализ, проверка и выпуск

Пайплайн передает модели только разрешенный контекст. Модель возвращает JSON по схеме с внутренними ID доказательств, редакций и судебных актов. Ссылки и цитаты собираются из записей сервером. Проверка ID и совпадения цитаты с текстом не подтверждает, что норма поддерживает вывод: это отдельная проверка применимости. Фрагменты вложений и источников считаются недоверенным содержимым; они не могут запускать команды, сетевые запросы или менять системные инструкции.

Заключение содержит 15 блоков: дело, обстоятельства, вопросы, нормы, точные ссылки, доказательства, позиция заявителя, позиция другой стороны, практика, ответственность, расчет, предварительный вывод, недостающие сведения, дальнейшие действия, проверенные источники. Блок без оснований объясняет причину отсутствия результата. Любой расчет возвращает формулу, входы, нормы, источник МРП и ограничения либо причину отказа. Гражданский ущерб требует собственной проверки состава, причинной связи и доказательств размера. Ни оценка модели, ни совпадение нормы не подтверждают вину или исход.

Жизненный цикл: черновик → на проверке → утвержден или возвращен → заменен новой версией. Утверждение привязано к конкретной версии, личности юриста и времени. При изменении содержания нужен новый просмотр. Экспорт до утверждения явно помечается как проект; API возвращает статус утверждения. Действия за пределами системы, в том числе отправка претензий, не входят в этот контур.

## API, эксплуатация и безопасность

Проект API этапа 2: `POST /v1/cases`, `GET /v1/cases`, `GET /v1/cases/{id}`, `POST /v1/cases/{id}/evidence`, `POST /v1/cases/{id}/analyses` (202 + ID), `GET /v1/analyses/{id}`, позднее — версии заключений, рецензии и артефакты. Схемы ошибок, лимиты, права и OpenAPI поддерживаются тестами контрактов. Технические ошибки каталога не выдаются за отсутствие закона. Метрики: глубина очереди, задержка, сбои источников, доля результатов с нехваткой данных, доля замечаний рецензента. Логи содержат ID и коды статусов без материалов дела.

Аутентификация через OIDC; роли оператора, юриста, куратора источников, аудитора и администратора. Разделение организаций проверяется на уровне сервиса и PostgreSQL RLS, включая фоновые задачи и выдачу вложений; роли приложения не обходят RLS. Файлы шифруются, карантин проверяет содержимое и размеры; OCR работает в изолированном процессе с лимитами. Резервные копии, удаление и восстановление входят в проверку внедрения. Аудит чтения чувствительных данных, изменений, утверждений и экспорта защищается от изменения ролями приложения.

Внешний LLM и внешние эмбеддинги для материалов дел отключены по умолчанию. Включение требует утвержденной политики, контроля отправляемых полей, места обработки и договора с провайдером. При отсутствии допуска — локальная модель или извлечение вручную. До внедрения согласуются условия хранения, передачи, доступа, резервного копирования и удаления с учетом [закона о персональных данных](https://old.adilet.zan.kz/rus/docs/Z1300000094).
